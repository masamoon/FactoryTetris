# Asteroid Works — playable implementation

Implemented 2026-09-20 after the user's explicit implementation request. This is the bounded side-view experiment approved in [the independent review](reviews/2026-09-20-implementation-review.md); the longer-term asteroid direction remains a hypothesis.

## Playable loop

1. Hold three exposed plain-rock blocks to earn six ore. Each removed block is finite; buried blocks cannot be targeted through solid rock. Plain blocks yield two ore; gold veins yield four.
2. Place a six-ore shaft drill in a cleared square facing right. It excavates an eight-cell section. Its head advances; real payloads return along the internal rail to the stationary base. The full corridor is reserved.
3. Lay free directional conveyors from the base's left output to the collection dock. Each transfer advances cargo at most one square. Full outputs stop the upstream machinery without discarding material.
4. Spend eight ore on a smelter: two ore become one plate. Replace an empty conveyor to insert it into the line. Feed from the right, output left. For recovery, tap COLLECTION and a compatible processor to dispatch one real recipe batch with the service drone when its four-item input buffer has room.
5. Collect six plates to build an assembler: two plates become one part. The first delivered part opens a real expansion fork. Either spend that part to extend the exhausted fixed-base drill by another eight cells, or combine it with two retained ore to place one new drill at the authored nearer rich face.

The extension can be committed only after the original section and every returning load are clear. It atomically reserves the next full corridor, sends a visible tender from base to head at rail speed, then resumes automatic excavation with the same eight-item output capacity and the longer real return distance. The bounded experiment permits one extension globally and at most two drill bases. It has no repeatable reach stat.

The authored starter route uses three manual blocks at x8/y5–7, a drill at x7/y6, conveyors x2–6/y6, a smelter replacing x4, then an assembler replacing x3. This is a reproducible path, not a claim that it is the only viable arrangement or that the current economy creates meaningful long-term alternatives.

## Controls and recovery

Hold or tap exposed blocks to mine; input is capped at ten work per second. Drag pans in either axis and cancels mining. Dock resets the view near collection. Select a tool, tap a square, and confirm. Construction previews and tools pause time; processors and drills resume after confirmation, while belt planning stays paused until Resume. R rotates conveyors, Enter confirms, Escape cancels, Space toggles pause, arrow keys pan horizontally.

Tap a machine to inspect actual inventory, returning ore and status. Tapping COLLECTION enters manual-delivery targeting and highlights compatible processors; the inspector provides the same dispatch as an accessible alternate route. The service drone takes one or two real items immediately, follows a persisted terrain-clear route, reserves the destination slots, and transfers the cargo only on arrival while the rest of the factory continues ticking. It then returns before another dispatch. Delivery remains available while a processor is working or output-blocked, saves immediately and creates no undo checkpoint; undoing the preceding build still rewinds all later delivery and production. An exhausted drill's inspector shows exact extension and fresh-drill costs, explicit disabled reasons, and View head/View base controls. Choosing the fresh drill opens a normal placement preview at its authored rich face; it does not construct automatically. Only empty conveyors can be replaced or removed. Undo build rewinds the complete outpost to before a committed edit, including all later courier deliveries, production and excavation. Up to 40 edits are retained subject to a 2 MB save budget. No-op edits create no history. Restart asks once and affects only this prototype.

The save contains terrain, partial work, stocks, buffers, return loads, courier cargo/route/progress/return state and undo history. It saves every second and after edits; unavailable storage is indicated. It uses a separate namespace from the tile workshop. Hiding the document and opening dialogs pause production and cancel mining. Returning or reloading does not award offline output.

## Evidence and remaining risks

The real simulation replay reaches the first part at 393 ticks (39.3 simulation seconds) with exactly one part and two ore available. From that same state, the extension branch removes its first new block at tick 443; the fresh-drill branch delivers its first ore at tick 450 after the replay constructs the second route. These are deterministic first-consequence witnesses, not human timings or evidence that either choice is enjoyable.

Automated tests cover exposure, tap/hold rate limiting, finite extraction, capacity and backpressure, return travel, one-cell transport, full-chain conservation, atomic invalid actions, undo, history limits and semantic save rejection. The extension additions also cover the equal-net authored fork, corridor reservation, tender timing, maximum-distance return, global caps, invalid empty corridors, save/resume and undo. Courier coverage adds truthful in-flight conservation, destination reservation against belt contention, repeat delivery, processor startup, exact save/resume, legacy-save migration and full-state undo. Validation on 2026-09-22: all 46 simulation/persistence tests and all 14 asteroid browser tests passed. The real browser trajectory reaches the earned fork through the UI, while separate touch tests exercise collection targeting and drone delivery at 360 × 640 and 390 × 844. Portrait captures were inspected. TypeScript, ESLint and the production build passed; Webpack retains its existing warning for the 1.23 MiB Phaser/application bundle.

The independent audit also ran 30,000 simulation ticks with 300 material-conservation samples; it found and prompted fixes for unbounded saves, impossible saved inventories and stale mining holds after pause. That is correctness evidence, not engagement evidence.

No character walking, jumping, gravity, falling rubble, energy economy, branching splitter, repeatable machine upgrades, offline production, prestige, multiple asteroids or tetromino footprints are implemented. The side-on viewpoint is inspired by the requested Terraria framing; controls remain direct remote mining. This prototype deliberately stops short of claiming a complete incremental game.

The straight starter line is easy to reproduce. The one-extension/two-drill cap intentionally leaves later depletion unresolved. Existing machines cannot be relocated after their edit drops out of undo history. These constraints are visible prototype limitations, not validated long-term design decisions. The next human playtest should establish whether players understand the extension-versus-new-site trade, notice the tender and longer return time, use head/base navigation, and experience expansion as planning rather than a compulsory maintenance prompt. The authored economy equalizes net ore after construction; it does not prove equal strategic value or prevent a dominant choice in wider terrain.
